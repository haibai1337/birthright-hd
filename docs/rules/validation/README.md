# Read-only Anuire economic calculations

Supports [economic validation](../BIRTHRIGHT_15_ANUIRE_ECONOMIC_VALIDATION.md), [character conversion](../BIRTHRIGHT_15_ANUIRE_CHARACTER_CONVERSION.md), [courts/growth](../BIRTHRIGHT_15_ANUIRE_COURT_AND_GROWTH.md) and [remaining decisions](../BIRTHRIGHT_15_ANUIRE_ECONOMIC_DECISIONS.md). J01–J08 are fixed. Every cost/conversion alternative is an analytical parameter, not an implemented rule.

Run from the repository root:

```powershell
node docs/rules/validation/calculate-anuire.mjs
```

Uses existing installed Vite to read the existing TypeScript scenario/forecast modules without a browser server or application build. Do not run import/settlement commands to reproduce this study. Inputs are existing `reference/extracted/anuire/{anuire,economy,magic,strategy,initialization}.research.json`; retained canonical output is `reference/research-cache/birthright15/anuire-validation/calculation.json`. It contains exact signed monetary units and detailed joins. The native campaign source is `RLMSTART.DAT`, hash recorded in the existing source/register sidecars. No proprietary historical implementation is copied into these calculation files.

Money in canonical JSON is **integer units of 1/120 GB**. Columns ending `U` use that scale; CSV columns ending `GB` are displayed decimals and may repeat thirds. Expectations/probabilities are floating-point analytic quantities. Income/expense balances are checked in integer units. This does not change the game's tenths-based schema.

Military `native` is the recovered HD profile upkeep **without** NPC exemptions; `active` is Sierra muster price/2; `garrison` is all units at muster/4, an explicit lower bound with unverified home eligibility. These prices do not substitute full BRCS war-card conversions. Four non-recruitable monster prices are flagged. Court `opening` is 1 GB; `expectedHolding` is maximum non-Source holding level, a hypothetical expectation, not a forced increase. Fort `upper` is all levels ×2/3; `towerAnalogue` prices the three wizard towers at 1/3 instead; `flat` is native 1 GB/asset. Additional port fee is 1/2 GB for each of 11 seaports, never a change to approved port **income**. Inactive/controller rows are potential arithmetic only.

No current subsidies, RP conversion, missing salaries, speculative routes or unknown infrastructure are added to make a faction solvent. Zero recorded contractual payments are distinguished from missing historical obligations. Existing holdings are never merged/deleted/normalized in source data. Forecast comparison has no Law Claims enabled, matching initial HD defaults; legacy ordinary Claims are not added to the 1.5 model.

### v1.0 finalization supplement

The [consolidated implementation contract](../BIRTHRIGHT_15_RULES_SPEC_V1_0.md) supersedes earlier unapproved parameter recommendations. J01–J08 and V02–V13 are approved; V14 means **unlimited RP storage**. The old stock-cap sensitivities remain historical comparisons, with no authority to truncate balances. V01 is still a candidate.

Run `node docs/rules/validation/finalize-v1.mjs` for the narrow supplement only. It reads the retained canonical calculation without importing application code or repeating extraction/simulations. [v1-approved-costs.csv](v1-approved-costs.csv) retains all 51 domains and reprices selected native military/flat forts/NPC exceptions; qualified Source cash remains conditional, with no fabricated handler appointment. Mieres/Chaos have blank ordinary settlement results. Monetary values are exact fractional GB strings. [v1-bloodline-candidate.csv](v1-bloodline-candidate.csv) retains all 80 ruler/domain combinations, unlimited stock and explicitly provisional RP bounds without assigned ranks. [v1-finalization-summary.json](v1-finalization-summary.json) records input/script hashes, totals and limitations. This supplement does not rewrite the original study or certify final skills/RP/long-term balance.

Growth uses only existing original holding contacts, spare capacity, positive-owner limits, Source-caster screening and realm-action groups of one type within a common host sovereignty. A holding gets at most one attempt per case; new contacts/Province Rule/repeated attempts/opposition/rank synergies are excluded. DC is 10+H with **no own-holding bonus**. Expected results assume zero other modifiers, not authentic rank zero. Mature courts require separately disclosed Decrees/years of spending and potentially palaces; candidate seat permissions and construction time remain unresolved. These cases are bounded examples, not a globally optimal expansion solver.

The calculator asserts coverage, receipts from asset/domain joins, all 1,836 balance equations, probability conservation and unchanged state/scenario/source hashes. An additional independent Python `Fraction` recalculation checked all 51 opening ledgers against raw records, all sensitivity balances and links; its [verification record](independent-verification.json) is retained alongside the outputs. It generates research outputs only. The human reports interpret these outputs; rerunning the calculator does not automatically rewrite report prose. No application tests/builds or source extraction are part of this research command.

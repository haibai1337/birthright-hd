# Oryginalne wydarzenia vs Birthright HD — macierz zgodności

> **Historical pre-implementation HD snapshot.** The campaign-event implementation now supersedes the HD status statements below. See [implementation report](CAMPAIGN_EVENTS_IMPLEMENTATION_REPORT.md), [options](CAMPAIGN_EVENT_OPTIONS.md), and [test matrix](CAMPAIGN_EVENTS_TEST_MATRIX.md). Treasury Incidents defaults Off by explicit user decision. The Windows 1.03 binary remains unverified; other recovered ally-exclusion builds are covered in the version comparison.

## Zasady porównania

Oryginał odnosi się do dostępnego checkoutu C++ (`GAMEMAP.CPP::DoRandomEvent/RandomEvents`), a HD do bieżącego [`packages/core/strategic-events.ts`](../packages/core/strategic-events.ts), wywołań w [`packages/core/engine.ts`](../packages/core/engine.ts) i tekstów w [`packages/ui/strings.ts`](../packages/ui/strings.ts). Nie porównano retailowych wydań 1.02–1.04. Szczegóły zachowania oryginału są w [inwentarzu](ORIGINAL_RANDOM_EVENTS_INVENTORY.md); kolejność faz w [flow](ORIGINAL_EVENT_PROCESSING_FLOW.md).

Status **częściowo** oznacza, że istnieje code path obsługujący podobny identyfikator/skutek, ale nie spełnia równocześnie warunków oryginalnych co do scheduler-a, targetu, fazy, prezentacji i edge cases. Nie używam statusu „implementowane” tylko z powodu podobnej nazwy.

## Scheduler i wywołanie

| Wymiar | Oryginał | Birthright HD | Ocena |
|---|---|---|---|
| Wywołanie/faza | `UpdateDataArea`: końcowy `ACTN_MODE` → raport (`++date`, `GiveReport`) → `REPORT_DONE_MODE` → `RandomEvents()` → `DoNPCAdmin()`. | `finishSeason`: rozliczenie, okupacja, dyplomacja, `turn++`, czyszczenie timerów → `generateEvents`; w profilu PC wywołuje `strategicEvents`. | **Częściowo** — eventy działają w końcu sezonu, lecz nie w identycznym miejscu względem ekonomii/raportu/AI. |
| Liczba prób | `random(5)+2` jako górna wartość pętli inclusive → 3–7 prób. | `randomInt(state,3,7)` → 3–7 prób. | **Zgodna liczba zakresu**, nie zgodna sekwencja losowa. |
| Data rozpoczęcia | `date` startuje 0; po initial report jest 1; RandomEvents kończy się gdy `date<2`, więc standardowe próby pojawiają się przy pierwszym końcu sezonu (`date=2`). | Campaign startuje `turn=1`; `finishSeason` zwiększa do 2, ale `strategicEvents` zwraca jeśli `turn<3`. | **Niezgodne: opóźnienie o sezon** względem mapowania tych liczników. |
| Pula 9/18 | Easy: 9 do `date<4`; Medium: do `<3`; Hard: do `<2`, potem 18. | `early = turn-1 < (victoryTarget===300 ? 4 : victoryTarget===500 ? 2 : 3)`; wybór puli 0–8/0–17. | **Niezgodne** — używa `victoryTarget` jako proxy trudności i przesuniętego `turn-1`; testy nie dowodzą zgodności dla trudności. |
| Kolejność losowania | Najpierw cel prowincji, potem event. Ostatnia próba kierowana do prowincji `HomeRealm` tylko single-player; dla 1–2 własnych prowincji istnieje szansa pominięcia. | Najpierw liczba prób, następnie cel, następnie indeks eventu; ostatnia próba wybiera prowincję gracza z analogicznym `max(3, own.length)` fallback. | **Częściowo zgodne intencją**, dokładny target/order/probability nie jest zweryfikowany; standardowa pula dodatkowo opóźniona. |
| Powtórzenia i retry | Wielokrotne indeksy dopuszczone; pusty efekt/limit/niepowodzenie `CreateUnit` nie powoduje reroll. | Wielokrotne indeksy dopuszczone; `applyOriginalEvent` wywoływany raz; nieosiągalne prowincje pomijają próbę. | **Częściowo zgodne**; inne guardy/limity i event scheduling RNG. |
| Tryb multiplayer | Wszystkie prowincje losowe (brak player-directed ostatniej próby); Gorgon ally score używa losowej korekty; inny limit NPC units; adventure sites host/master only. | Nie ma odrębnego multiplayer event scheduler-a w `strategicEvents`. | **Brak / wymaga weryfikacji** dla multiplayer. |
| Trudność/tryb | `game_difficulty` steruje pulą, grantem NPC i rozmiarem spawnów; `fControlMode` osobno wpływa na Basic/Tutorial. | Nie ma difficulty field w event logic; `victoryTarget` zastępuje difficulty. Brak tutorialowego wczesnego wyjścia/bonusów. | **Niezgodne**. |
| Losowość | `random(num)` skaluje platformowe `rand()`. Kolejność może być współdzielona z innymi wywołaniami źródła. | Seedowany `randomInt` mutuje serializowany `state.rng`. | **Celowo inny model**; wyniki nie będą replay-identyczne z retail. |

## Co potwierdzają obecne testy

[`tests/fealty-initialization.test.ts`](../tests/fealty-initialization.test.ts#L211) testuje pojedynczy event 12 (profile 26) oraz mapowania 9–16, deterministyczność eventu 8/serializację i 3-graniczne wygaśnięcie. [`tests/strategy.test.ts`](../tests/strategy.test.ts#L395) sprawdza `synchronizeRebellions` i deterministyczność scheduler-a. Nie znaleziono testów dla dystrybucji prób, off-by-one fazy, puli zależnej od difficulty, targetowania eventu 17, kwot ID 0–3, okresowych spawnowań, Gorgon Plot ani zgodności native report text. Testy nie stanowią dowodu pełnej zgodności macierzy.
